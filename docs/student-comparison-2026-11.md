# DUETBlox student workflow comparison — 26 November 2026

This comparison was cross-checked on **26 November 2026** against official competitor documentation and the current DUETBlox source, including the 0.9.6 workflow additions. It distinguishes documented capabilities from demonstrated behavior. It is not a study with children, a head-to-head performance benchmark, or physical-board certification. A larger feature list does not establish better learning outcomes or make DUETBlox the best overall.

## Fresh cross-check evidence

The 26 November cross-check used the deployed 0.9.6 pack `3e48b3b78e2544f94291` as its baseline, separate temporary browser profiles and synthetic test projects. The follow-up fixes retain version 0.9.6; their generated pack and final verification are recorded in the release handoff.

- **Core checks:** 439 unit/service tests passed after the connection-guidance regression was added. The 40 Scratch adapter tests and three dialog component tests passed. The editor harness needs the same `/duetblox/` mount as its built assets; an initial run using `/` was invalid, and the mount-corrected run passed without a product change.
- **Public-browser checks:** the full baseline run passed 105 cases and failed its private-classroom connection case because Chrome denied public-site access to loopback before any request reached the test server. The full assignment/submission/feedback workflow then passed with explicit local-network consent in disposable browser contexts. A second test verified denial, zero received requests, and successful reconnection after consent. No user browser permissions or security flags were changed. This does not prove multi-device classroom deployment.
- **ML computation:** an 11-stage production-build probe trained and predicted with image, sound, pose, text, numbers and object-finder models. Numbers covered classification and regression. All six Scratch extensions executed, an 18,997,821-byte combined `.duet` project restored its models and predictions, and six-model inference/Blocks ran after a cold offline reopen. There were no page errors, external requests or camera/microphone calls in this probe. Synthetic shapes/tones and augmented photographs establish pipeline execution, not real-world accuracy. Fresh neural training while disconnected and external Teachable Machine URLs were not exercised in this cross-check.
- **Object-finder limitation:** on one synthetic holdout image the experimental method matched one object and returned five extra boxes (17% precision, 100% recall for that single image). This is a useful failure example, not a representative benchmark. A trained crop classifier and window search must not be described as equivalent to a general detector.
- **REA runtime evidence:** a declared fresh-browser scenario opened the built-in Junior starter, waited for the desktop Play control, ran it, and observed both “Story finished” and the success celebration, with no page errors. All six declared steps completed; evidence ID `ev_a7c35166dff84b8b7cacfef90afae7831f57521a09b8d6295e88065b6203d560`. This is one controlled workflow, not whole-platform certification or a native-binary analysis.
- **Usability fixes from this pass:** compact navigation now displays workspace names, avoids the clipped section heading, exposes the active page semantically, and gives Help an explicit accessible name. Keyboard Help and workspace changes were checked at phone, narrow-window and desktop sizes. Classroom errors now explain local-network permission as one possible cause alongside server/address/origin setup. README build and test instructions now identify the current branch and mount.

The local evidence folder is `work/crosscheck-20261126/` in the laptop checkout. Logs, fixture reports and REA captures are evidence from the stated runs; they are not a claim that all possible inputs, browsers, boards or classroom conditions were tested.

## Corrections to older comparisons

- **Python is present.** It is a separate browser text workspace, without Scratch-to-Python conversion, a notebook interface or Python board upload. See [Python scope](python.md).
- **Numerical classification/regression is present.** Supported numerical models can be embedded in generated board C++. Image, sound, pose and text models do not become embedded programs through that path. Real sensor/model combinations still require physical tests. See [number learning](number-learning.md).
- **An object finder is present, with a limited method.** It learns image-crop classes and searches a bounded set of square windows in still photos. It does not learn bounding-box coordinates, use a general YOLO/SSD detector, or establish real-time object-detection parity. See [object method and limits](object-learning.md).
- **Debugging and simulation are present.** The synchronous Learning steps subset, breakpoints, wired circuit solver, Uno HEX execution and separate ngspice replace the old “no debugger/simulator” description. They do not provide full asynchronous debugging or coupled MCU/analog simulation.
- **Classroom assignments and private review are present.** A receipt authorizes access to one submission; it does not verify the student's identity. Publishing browser files does not start the teacher-run server. See [classroom setup and privacy](classroom.md).
- **Direct starters are no longer Junior-only.** All 13 current lessons have protected starter paths. This does not mean every ML modality or hardware task has a guided lesson.
- **Local-browser ML is not unique.** mBlock and Teachable Machine already document it. DUETBlox's combined project format and workflow should be evaluated on actual student tasks rather than presented as an unsupported overall lead.

## Changes made in 0.9.5

1. The home screen presents three concrete first activities with reading-sized text and controls: a first Junior story, guided lessons, and Circuit Lab without a physical board. Existing workspace cards explicitly continue current work.
2. Junior's lesson starter opens directly. The entire previous workspace is validated and stored as a recovery copy before replacement. Failed recovery or persistence leaves the current story intact. It does not erase Scratch code, circuit work or ML models. No activity runs automatically.
3. Learn and My projects move above advanced workspaces in the sidebar. Sidebar labels are larger; advanced choices have a separate heading.
4. The unconditional “Saved on this device” label is removed. Save feedback reflects actual completed IndexedDB transactions, including persistent failures and a downloadable backup action. Successful writes to unrelated records cannot dismiss an existing failed save. The label deliberately describes the last browser write, not a guarantee that every pending editor edit has been serialized.

## Student usability acceptance

Engineering checks cover: locate the first activity; open and run it; retain an in-editor guide; restore prior Junior/circuit work; recover from a simulated full storage condition; download a valid project despite a browser save failure; and reach primary controls by keyboard at 1366×768 and 390×844 without horizontal page overflow. These checks do not establish reading comprehension or child preference.

Next classroom pilot: observe a small group across beginning readers and experienced Scratch students, with teacher support. Ask each student to start a story, change one action, explain the result, save/reopen it, and try a virtual LED. Record anonymous task completion, time, where help was needed and whether saving/simulation were understood. Do not invent a numerical usability score before that pilot.

## Changes made in 0.9.6

- Every one of the 13 built-in lessons has a protected direct starter: Junior story/decision, animation/game/quiz/Pen/Music, image/text examples, virtual board programs and Python. No file download/reopen round trip is needed. Existing complete work is recoverable before the relevant program/dataset changes. Old Scratch events are removed from a lesson copy to prevent unrelated programs from running together. ML models for replaced examples are cleared only after durable commit; other modalities remain intact.
- Learn has a workspace filter, larger instruction text and the starter action near the lesson heading. Lessons retain English, Hindi and Hinglish explanations; the entire application interface is not fully translated.
- Circuit Lab teaches LED/resistor, button/pull-up, potentiometer/ADC and sensor-controlled LED. Students may start with loose parts and build the wiring, inspect solved connections, compare current/voltage/readings, and open matching Blocks programs. Circuit replacement has its own persisted recovery. A traffic-light starter includes three wired LED/resistor branches.
- Learning steps can run to a chosen supported command, pause before it, inspect values, and step. Unreachable breakpoints stop at a bounded 100-step budget. This remains a core synchronous subset, not a general Scratch timing debugger.
- Private classrooms have teacher assignments, private submissions and review feedback. Students keep a room/server-scoped receipt to retrieve the specific submission it authorizes. Anyone with that receipt and the room key can access that submission; the receipt is not identity authentication. The updated teacher server must be run on the LAN; publishing static browser files alone does not install that backend. Aliases are self-reported, not individual authenticated identities.
- Board-specific observation sheets distinguish software checks from real connection, upload, outputs, input, Stop/watchdog and independent-power tests. Reports remain explicitly self-reported and do not change the software's physical-validation status.

## Remaining priorities and acceptance criteria

1. **Real hardware and adapter coverage:** connect Uno R3, classic Nano, Mega 2560, ESP32-WROOM and AI Thinker ESP32-CAM and verify USB connection, upload/read-back, outputs, sensors, Stop/watchdog and independently powered execution. No board was connected during this work. Software builds and observation sheets do not close that gap. ESP32-CAM camera/SD blocks, additional ESP variants, Uno R4/Alvik and other vendors' robots need their own supported adapters and actual devices; catalogue entries are not working integrations.
2. **Student usability and accessibility:** run the pilot above with beginning readers and experienced Scratch students. Check touch, keyboard and screen-reader use on classroom devices, and record task completion and help needed. Automated viewport/workflow checks do not prove reading comprehension, child preference or learning outcomes. Complete application localization remains separate from the existing translated lessons.
3. **Simulation and debugging depth:** implement and validate additional asynchronous/event debugging and peripherals where required. The current Uno CPU runner, five logic profiles and static SPICE snapshot are not ESP32 CPU emulation or real-time MCU/analog co-simulation. Compare solver/firmware outputs against reference cases before making accuracy claims.
4. **Teaching and ML breadth:** extend the 13 lessons and four circuit guides with sound, pose, object and numerical activities, including held-out examples and failure cases. Broader detection/hand-pose work and media-model deployment to microcontrollers require explicit implementation and tests. The current experimental object finder and small linear numerical models must keep their method limits visible.
5. **Classroom administration:** validate the updated server on the intended LAN/HTTPS setup. Individual student authentication, practical retention/archive administration and richer teacher workflows remain beyond the shared-room-key prototype. Private submissions and feedback are useful additions, not an enterprise classroom platform or an identity-based grading system.
6. **Update lifecycle and platform coverage:** the retained in-app browser now loads the updated app after the project-preserving recovery procedure, and targeted update tests cover **seven migration cases**. The earlier timeout is therefore not the last observed outcome. Broader browser/device and multi-window coverage remains pending. Prepare the current offline pack after updating; remote services, unprepared toolchains and initial downloads still have connectivity requirements. Browser/PWA use is not a signed Windows desktop release.

No new complete-platform test total is claimed by this comparison; completed release checks are recorded separately. The evidence gaps above remain open. This document makes no universal “best”, “bug-free”, comparative-accuracy or hardware-certification claim.
